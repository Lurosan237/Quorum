What each server has written down

One square per log entry, coloured by the term it was written in. Filled squares are committed: a majority has them, so no future leader can lose them. Hollow ones may still be overwritten. Older entries are folded into a snapshot.

What just happened

    Break it on purpose

    A checker that never fails proves nothing. Each run below is one whole recorded run, at full speed, with a bug planted in it; the checks must catch it. Then the same seed again with the bug removed.

    Forget client sessions

    Without them, a retried append is applied twice when the first answer got lost. Flaky mobile data, seed 1.

    Forget a vote after a power cut

    A server that votes, loses power before saving the vote, and votes again lets two leaders win the same term. Brownouts, seed 292.

    Why power cuts

    I study in Bertoua, Cameroon, where the power and the internet go out often. A store that keeps answering through that, and never gives a wrong answer, is the one I wanted to build.

    The same code, for real

    This Raft runs here unchanged as five separate servers with an on-disk log. On every push, CI kills them, freezes them, cuts the network, blacks them all out at once and checks hundreds of thousands of answers.

    Reads too

    A leader cut off from the others may not know it was replaced. Before answering a read, it confirms with a majority that it is still the leader (ReadIndex), so it never serves a stale value.
